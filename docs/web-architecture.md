# Web query and presentation boundaries

The server-rendered web application is split into three focused layers under `src/web/`:

- `web.rs` owns Axum routing, request extraction and validation, server-side session middleware composition, login/logout orchestration, sanitized HTTP error mapping, and final Askama rendering. `auth.rs` owns persistent application identities, Argon2id verification, session identity/expiry/revocation checks, CSRF tokens, and CLI account operations. Data handlers coordinate the query and presentation layers but contain no SQL or transcript classification rules.
- `queries.rs` owns SQLite row types and reads for session pages, filter values, runtime project classification, source-layout display state, historical usage aggregates, turn history, pressure/diagnostic summaries, postmortem aggregates, the one-row live status probe, timeline sections, and lazy message/tool chunks. Query limits remain next-page-aware: 51 session rows for a 50-row page, 101 usage rows for a 100-row page, 20 recent usage observations, 51 turns for a 50-turn page, 50 pressure snapshots, 20 evidence rows per diagnostic category, and 51 events for a 50-event timeline section. Project expressions and every filter value are parameterized. Event projections and detail chunks retain the documented character limits.
- `presentation.rs` converts query results into filter options, usage availability/ratio views, turn summaries/evidence links, and source-ordered timeline items; groups consecutive assistant replies only across adjacent messages; applies source-dispatched message classifications; assigns tool/question states; and constructs safely encoded navigation links. It has no database or HTTP dependencies.

`src/postmortem.rs` is a separate export presentation boundary. It converts one aggregate query row into the versioned redaction contract, allowlists exported labels, emits only fixed reason codes, and renders deterministic JSON or Markdown without depending on HTTP or raw source parsing.

Source-specific interpretation remains in `src/sources/`. The query layer applies the generic source policy returned by that dispatcher, while presentation asks it how a stored message should be labeled and opened. Neither web submodule inspects raw Codex JSON.

The database-backed route tests exercise the boundaries together, including composable project/date/archive/agent filters, stable filter pagination, filtered-empty states, direct-home origin suppression, source-specific hidden models, fixed-timezone usage periods and grouping, usage reconciliation and bounds, paginated turn history with duration/model/tool evidence, pressure freshness and bounded diagnostic evidence, adversarial redacted postmortem exports, opt-in live status and concurrent committed replacements, bounded timeline sections, large message/tool parts, tool/question/turn/diagnostic filters and states, initial and resumed setup classification, ordinary conversation, authentication, and sanitized errors. Unit tests cover path grouping, date validation, transcript grouping, Markdown escaping, and URL encoding directly.

Project navigation, the usage dashboard, postmortem export, and live reading add reads but change no raw parsing. Turn and pressure history require parser version 7 evidence. Live reading adds nullable source-observation state automatically; run one refresh to populate it. No full rebuild is required. Restart the server to load code or project-configuration changes.
