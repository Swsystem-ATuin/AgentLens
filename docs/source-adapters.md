# Source adapter boundaries

Agent Lens stores generic agents, instances, sessions, ordered turn/model evidence, messages, tool calls, ordered tool results, and usage events. Source formats are translated before database orchestration or presentation rules consume them.

The adapter boundary lives under `src/sources/`:

- `mod.rs` defines source-neutral discovery results, normalized record variants (including turn/model signals), cumulative/per-turn token scopes, source layouts, and message-presentation dispatch.
- `codex.rs` owns the `.codex` host/user and direct-home contracts, active/archive locations, symlink-aware discovery, parser version, two-pass rollout reading, streamed optional advisory titles, session metadata and lifecycle reduction, message/tool/turn/usage interpretation, Codex-only hidden-model policy, and recognized setup/notice markers.
- `gemini.rs` owns `.gemini` discovery, current JSONL and legacy JSON chat-loading semantics, checkpoints/rewinds, embedded tools, per-turn token observations, and Gemini message presentation. Its pinned raw-format and capability contract is [documented separately](gemini-adapter.md).
- `ingest.rs` owns rebuildable-index concerns: transaction and savepoint boundaries, checkpoints, instance/session upserts, normalized SQL writes, replacement rollback, pruning, and report totals. It dispatches adapters but does not inspect their raw JSON fields.
- `web.rs` queries the indexed `agents.kind` and asks the source dispatcher for optional message presentation. Unknown kinds receive ordinary open message rendering. Codex-only model suppression is conditional on that same kind, so similarly named models from other agents remain visible.

Codex and Gemini CLI are configured discovery adapters. Adding another source requires its own module and explicit dispatch rather than adding foreign raw-field checks to ingestion or web code. Unknown raw fields and record types remain local non-fatal omissions, and useful raw JSON remains attached to normalized records where the schema supports it.

## Compatibility and verification

Context/rate evidence changes rollout interpretation, so the Codex parser version is now 7. Existing indexes upgrade automatically, retaining order-unknown legacy tool/usage evidence without inventing turn or pressure history, but one refresh is required to recover exact output order, compute token summaries, populate turns, and retain pressure snapshots; no rebuild is required. Gemini starts at parser version 1. Existing synthetic regression coverage verifies discovery failures, symlinks, malformed and partial lines, schema variants, lifecycle and turn ordering, terminal-only/unclosed/resumed work, requested-model changes and served fallbacks, replacement rollback, repeated tool IDs, orphan/structured/failed outputs, unanswered questions, cumulative resets/duplicates/gaps/resumes, usage subsets and inconsistencies, context/rate sparsity and null-info variants, title precedence, rendered initial/resumed transcripts, and ordinary conversation. Mixed-source regressions verify identity isolation, shared project and agent views, Gemini checkpoint/rewind and legacy JSON behavior, rebuild/refresh parity, unsupported lifecycle and aggregate-usage semantics, adapter-specific initial/resumed presentation, and preservation of ordinary conversation.

The ingest path was remeasured with the existing synthetic 60,000-message, 65.2 MB rollout. Three warm-cache full rebuilds used separate SQLite outputs and the same source. The pre-adapter bounded importer (commit `409f1e3`; later R1.2/R1.3 commits did not change ingestion) had a 6.652-second median and 14,540–14,820 KiB sampled peak RSS. The adapter implementation had a 6.276-second median and 14,896–14,964 KiB peak RSS. The elapsed ranges overlapped and sampled memory remained within about 1% at the upper bound, showing no material throughput or memory regression. These local warm-cache measurements are not general latency guarantees.

R5.1 was measured separately against its immediate baseline, commit `609d2f4`, using release binaries and the same generated 40-session, 60,000-message Codex tree (67,280,431 directory bytes). Three alternating warm-cache rebuilds used separate SQLite outputs. Baseline elapsed time was 7.934 seconds median (7.766–8.070); R5.1 was 7.914 seconds (7.733–7.934). Sampled peak RSS was 14,620–14,964 KiB before and 14,856–14,944 KiB after. Process character I/O was effectively identical at about 1.628 billion bytes read and 575.967 million written per run; physical reads were zero in the warm-cache sample. The additional Gemini discovery pass did not materially change Codex rebuild throughput, memory, source passes, query volume, or writes.

A current-only Gemini stress case used one generated 60,000-message JSONL chat (63,697,933 directory bytes). Three warm-cache rebuilds took 8.192 seconds median (7.967–8.572) with 227,388–227,460 KiB sampled peak RSS and about 1.683 billion process characters read and 503.814 million written. The higher memory is expected from retaining the active message set and queued normalized events required by checkpoint/rewind semantics. Message-ID lookup uses an indexed in-memory position map, keeping append, replacement, and rewind bookkeeping linear rather than repeatedly scanning the active transcript. All benchmark content was generated placeholder text; no private source was read. Polling can miss brief peaks, and these local measurements are not general performance guarantees.
