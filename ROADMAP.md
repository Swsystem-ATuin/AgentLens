# AgentLens roadmap

Updated 2026-10-12. This is the single backlog for planned features, architecture work, and conditional decisions. It incorporates every open item from the 2026-09-09 architecture TODO and the [feature comparison](docs/feature-comparison.md) of codex_viewer, codex-dash, and codex-blackbox. All unchecked items are unimplemented proposals; the confirmed multiple-user requirement now has an implemented source-scoped visibility policy.

Keep IDs stable, check items when delivered, and link the implementing commit or documentation. Milestones express dependency order, not delivery dates. Retain Rust, SQLite, server-rendered HTML, immutable raw sources, and a completely rebuildable index. Performance benefits are hypotheses until measured.

## Delivery sequence

| Milestone | Outcome | Dependencies / completion gate |
| --- | --- | --- |
| R0 — Reliability | Trust rebuilds, errors and status | First: protects existing data access and later reports |
| R1 — Bounded browsing and source boundaries | Read large datasets with bounded resources | R0; measure rebuilds and query/response bounds |
| R2 — Find and understand sessions | Titles, projects, search and richer transcripts | R1; durable identity before saved links or annotations |
| R3 — Usage and diagnostics | Explain consumption and problematic turns | R0 lifecycle semantics and R1 adapters; R2 tool views for drill-down |
| R4 — Incremental observation | Freshness-aware updates and optional collection | R0/R1; use M1–M4 before shared deployment |
| R5 — Wider observability | Additional adapters and optional metrics | R1 contracts; R3 accounting; M1–M4 for shared access |
| M — Accounts and access | Individual identities, enforced permissions, and account-management controls | M1–M4 complete the shared-deployment gate; M5.x builds on the persistent identity boundary |
| C — Conditional decisions | Evidence-based technology choices | Evaluate at the relevant feature/deployment gate |

Start with R0, then deliver R1 before expanding the browser workload. R2 and R3 can be scheduled independently once their stated prerequisites hold. M is a deployment gate, not a feature deferred until after R5.

## R0 — Reliability and correctness

The following five items retain the original TODO acceptance criteria.

- [x] **R0.1 — Preserve the usable index during rebuilds.** Build and validate a replacement before switching over. Explicitly manage active database connections and SQLite WAL/SHM files. Verify that failed or interrupted rebuilds preserve the previous index and that a successful switch serves the new data. Document the supported procedure when the web server is running. Delivered with staged, validated publication; [behavior and verification](docs/rebuild.md).

- [x] **R0.2 — Report incomplete source discovery.** Replace silently ignored directory and traversal errors with useful, sanitised diagnostics and an accurate ingest result. Verify missing and unreadable sources cannot look like a successful complete import. Delivered with transactional missing-source cleanup; [behavior and verification](docs/refresh.md).

- [x] **R0.3 — Keep internal errors out of browser responses.** Return generic server-error messages while retaining sanitised diagnostic context on the server. Test that responses and logs do not disclose private transcript content or credentials. Delivered with source-free browser responses and allowlisted server diagnostics; [behavior and verification](docs/web-errors.md).

- [x] **R0.4 — Derive session status from event order.** Define completion, interruption, and resumed-session behavior, then cover those sequences with synthetic tests instead of relying on whether an event appears anywhere in a file. Delivered with an ordered, conservative lifecycle reducer; [behavior and verification](docs/session-status.md).

- [x] **R0.5 — Expand parser resilience tests.** Cover unknown fields, malformed lines, partial files, and observed schema variants with tiny synthetic or fully redacted fixtures. Verify useful records survive local parsing failures and diagnostics accurately describe partial imports. Delivered with retained raw-field/schema-variant coverage, valid-record survival across malformed JSON/UTF-8, exact sanitised line diagnostics, and separate CLI partial-file/malformed-line totals; [format contract](docs/fixture-format.md) and [refresh behavior](docs/refresh.md).

## R1 — Bounded browsing and source boundaries

These five items retain the original TODO acceptance criteria. The regression suite already covers several parser variants; the remaining work extends its guarantees rather than replacing it.

- [x] **R1.1 — Bound ingestion memory.** Evaluate streaming with bounded buffering against a two-pass parser where metadata discovery requires it. Measure representative full rebuilds before and after, including elapsed time and peak memory; review transaction boundaries, query volume, file I/O, and allocations. Report only aggregate results, without private content. Delivered with two-pass record streaming, bounded malformed-line examples, indexed tool-output pairing, preserved transactional semantics, and a synthetic before/after benchmark; [design and verification](docs/ingestion-memory.md).

- [x] **R1.2 — Paginate the sessions list.** Add bounded queries with stable ordering and navigation that preserves filters. Verify that larger datasets do not require loading every matching session for one page. Implemented with 50-row pages, a 51-row query ceiling for next-page detection, deterministic timestamp/ID ordering, safely encoded filter continuity, and rendered multi-page regressions.

- [x] **R1.3 — Load long transcripts in sections.** Bound database reads and rendered response size while preserving message order and sensible grouping across section boundaries. Collapsed content should not require transferring the entire transcript upfront. Delivered with 50-message/51-row sections, bounded message previews, lazy message-part navigation, section-aware grouping, and [documented query and response limits](docs/transcript-sections.md).

- [x] **R1.4 — Separate source adapters from generic application logic.** Move Codex discovery, parsing, and setup-marker recognition into source-specific modules. Keep normalised events, indexing, queries, and presentation generic; preserve existing behavior with tests. Delivered with a source-neutral record/presentation contract, a dedicated Codex discovery and streaming parser module, agent-kind presentation dispatch, cross-source policy regressions, and [documented boundaries and performance verification](docs/source-adapters.md).

- [x] **R1.5 — Separate querying and transcript presentation from route handlers.** Extract focused modules as part of the source-boundary refactor, keeping handlers responsible for request extraction and responses. Delivered with dedicated SQLite query and presentation/view-model modules, thin coordinating handlers, preserved route-level regressions, and [documented web boundaries](docs/web-architecture.md).

## R2 — Find and understand sessions

Inspiration: codex_viewer's reader and advisory names, and codex-dash's project navigation. See the [review and pinned sources](docs/feature-comparison.md). These are adaptations to AgentLens's web application.

- [x] **R2.1 — Stable session identity and readable titles.** Use an application-defined source identity plus agent-native session ID for durable links; never depend on rebuildable SQLite row IDs. Prefer valid advisory names where available, with a bounded conversation-derived fallback and native ID fallback. Keep discovery authoritative to rollouts. For Codex, read optional `session_index.jsonl` through the adapter, tolerate malformed/partial entries, and document the precedence rule. Delivered with reproducible source-scoped public IDs, streamed advisory-name enrichment, bounded conversation/native fallbacks, automatic disposable-index migration, and rebuild/collision/browser-route regressions; [identity and title semantics](docs/session-identity.md).

- [x] **R2.2 — Project navigation and useful filters.** Group working directories using configurable host-aware project roots, with optional subprojects. Add project, date range, archive state, and agent filters alongside existing filters; define timezone and date-boundary semantics. Include readable titles, last observed activity, stable sorting, and clear filtered-empty states. Test overlapping roots, Windows/POSIX paths, missing metadata, filter combinations, and pagination continuity. Delivered as read-only runtime grouping with bounded host/path rules, most-specific subproject matching, fixed-offset inclusive activity dates, stable activity/public-ID ordering, composable filters, and rendered edge-case regressions; [project navigation semantics](docs/projects.md). Manual assignments and context notes remain deferred to M2/M3.

- [x] **R2.3 — Search sessions and transcripts.** Start with title/native ID/project search, then indexed transcript search with bounded snippets and links to matching messages. Evaluate SQLite FTS in the disposable index. Preserve filters and pagination, escape search highlights, and enforce the same access scope on results, counts and snippets. Verify special characters, rebuild parity, large result sets, and setup blocks not obscuring ordinary conversation matches. Benchmark search-index rebuild overhead. Delivered with literal metadata search, disposable FTS5 transcript indexing, message-linked escaped previews, composable pagination/filtering, bounded candidate and response sizes, automatic legacy backfill, bulk rebuild construction, access-scope regressions, and a synthetic before/after benchmark; [search semantics and verification](docs/search.md).

- [x] **R2.4 — Safe rich transcript rendering.** Add Markdown/GFM, fenced code and tables while preserving current setup labels, interruption notices, grouped replies, and plain-text fallback. Disable raw HTML, unsafe URL schemes and automatic remote resource loads. Verify rendered HTML for initial/resumed sessions, malicious content, ordinary prose and section boundaries. Add optional math only after core rendering and resource limits are established; it is not a prerequisite for the reader milestone. Delivered with bounded CommonMark/GFM rendering, escaped raw HTML, image suppression, scheme-filtered links, a restrictive no-resource Content Security Policy, whitespace-preserving plain-text fallback, and rendered security/grouping/resume/section regressions; [rendering contract and limits](docs/rich-transcripts.md). Math remains optional and disabled.

- [x] **R2.5 — Tool and question/answer timeline.** Interleave messages with tool calls, results, and explicit user-input requests/responses using source order. Provide bounded previews, lazy details, event-kind filters and message/turn anchors. Preserve call/result identity across pages and refreshes. Distinguish requested, output observed, failed and unknown outcomes: the existing `complete` tool status only means an output was paired, not successful execution. Cover missing/orphan outputs, repeated IDs, malformed arguments, structured outputs, aborted questions and ordinary conversation in both domain and HTML tests. Retain provenance needed to reconstruct order; existing normalized tool rows do not contain a separate output sequence. Delivered with first-class ordered result rows, latest-preceding-ID pairing, explicit question/answer kinds, 50-event sections, bounded previews/lazy details, event filters, stable anchors, legacy-order disclosure, refresh/rebuild parity, rendered edge-case regressions, and a measured tool-heavy rebuild tradeoff; [timeline semantics and verification](docs/tool-timeline.md).

## R3 — Usage and turn diagnostics

Inspiration: codex-dash's usage views and codex-blackbox's evidence-based reporting. Implement historical analysis from available raw records first; proxy-only observations remain unavailable without an additional source.

- [x] **R3.1 — Correct token accounting.** Define generic cumulative-snapshot and per-turn usage semantics in source adapters. Current Codex ingestion stores every `total_token_usage` snapshot; summing those rows would double-count. Handle duplicate snapshots, counter resets, missing values, resumed sessions and inconsistent totals explicitly. Cached input is a subset of input; reasoning output, where reported as a subset, is not added to output again. Preserve raw evidence and label unavailable values rather than zero-filling. Test all cases with synthetic sequences and verify repeatable rebuild totals before any aggregate dashboard ships; require incremental parity when R4.1 is implemented. Delivered with generic usage scopes, source-ordered per-field delta reduction, reset/duplicate/missing/inconsistency evidence, non-additive per-turn observations, nullable summaries, raw provenance, legacy-safe migration, refresh/rebuild parity, deterministic benchmark totals, and an explicit R4.1 parity contract; [accounting semantics and verification](docs/token-accounting.md).

- [x] **R3.2 — Historical usage dashboard.** Show input, cached input, output, available reasoning detail and totals by session, model, project, host, user and agent. Add daily/weekly/monthly ranges, cache ratios, recent activity and drill-down. Define periods by event time and an explicit timezone; do not label a session's lifetime total as usage today merely because it was updated today. If only snapshots are usable, label the attribution limitation. Test period boundaries, unknown models, zero denominators and reconciliation from detail to totals. Monetary estimates are deferred pending versioned pricing and evidence about billing semantics. Delivered as an authenticated, bounded observation-time dashboard with all required groupings, fixed-offset calendar periods, explicit partial/unavailable and unattributed evidence, anomaly counts, recent stable-ID transcript links, and reconciliation coverage; [dashboard semantics and verification](docs/usage-dashboard.md). Monetary estimates remain deferred.

- [x] **R3.3 — Ordered turn and model history.** Normalize turn boundaries, requested models, completion, interruption, resumption and relevant tool outcomes. Show duration only where start/end evidence supports it, including the definition of that duration. Preserve unknown/unclosed turns; a recent file or last timestamp is not proof of activity or completion. Label a requested-model change separately from observed served-model fallback. Add sequence tests for resumed work, out-of-order timestamps and missing events, plus links back to the supporting timeline items. Delivered with a bounded source-order reducer, terminal-only and unclosed preservation, requested/served model separation, turn-associated tool summaries, 50-turn pagination, evidence links, automatic legacy-safe migration, and rendered/rebuild regressions; [semantics and verification](docs/turn-history.md).

- [x] **R3.4 — Context, rate pressure and diagnostic summaries.** Surface observed context-window and rate-limit snapshots with timestamps and source scope where present. Retain the necessary events even when token `info` is missing. Show expired/stale readings as such; do not infer current subscription allowance from copied data. Build deterministic summaries of interruptions, incomplete turns, accounting anomalies and observed failures, each with provenance and an explanation. No automatic blocking, generated quality scores or claims that an interrupted session failed its task. Verify sparse/unknown variants, freshness rules and links to evidence. Delivered with nullable context/rate fields on ordered usage evidence, current/legacy reset variants, explicit 15-minute freshness and expiry rules, a bounded authenticated diagnostics dashboard, four explained evidence-linked summaries, hidden/direct-home policy parity, legacy-safe migration, and rendered/rebuild regressions; [semantics and verification](docs/diagnostics.md).

- [x] **R3.5 — Redacted postmortems.** Provide a local report of turn outcomes, usage, model changes and known evidence gaps, with explicit redacted Markdown/JSON export. Require R3.1/R3.3/R3.4 and stable session identity. Default exports to aggregate facts and bounded reason codes; exclude prompts, source code, tool bodies, sensitive paths and credentials. Apply access permissions to export endpoints, document any included identifying fields, and test adversarial synthetic redaction cases. Reports must remain reconstructible from raw sources; saved user annotations belong in durable application state. Delivered with authenticated per-session JSON/Markdown downloads, a deterministic aggregate-only versioned contract, allowlisted identity/status fields, 14 bounded evidence codes, fixed filenames, hidden-session parity, and adversarial rendered/export regressions; [contract and verification](docs/redacted-postmortems.md).

## R4 — Incremental observation and collection

Inspiration: codex_viewer's incremental reader and codex-dash's freshness-aware pooled board. Copied homes remain immutable inputs; collector outputs and checkpoints must live elsewhere.

Incremental CLI refresh is delivered; see [refresh behavior and verification](docs/refresh.md). Checksums verify every file, changed projections replace atomically, legacy checkpoints upgrade automatically, missing-source discovery fails closed, and deterministic duplicate resolution converges with a fresh rebuild. R4.2 builds live presentation updates on this committed snapshot boundary.

- [x] **R4.1 — Incremental, idempotent indexing.** Add an explicit refresh path that detects new/changed sources and updates only affected records. Handle appended partial JSON/UTF-8, truncation, replacement, archive moves, duplicates and interrupted commits. Define how immutable snapshots are published and how appended sources are validated; do not silently inherit an upstream probe heuristic that can miss historical edits. Keep full rebuild as the repair path and all checkpoints disposable. Verify repeated refreshes and a fresh rebuild yield equivalent normalized data; benchmark full rebuild and incremental elapsed time, peak memory and file I/O before/after. Delivered with whole-file BLAKE3 verification, current-parser/status checkpoints, affected-file transactional replacement, per-file savepoints and run-level rollback, missing-source cleanup, partial-tail retry, full rebuild repair, deterministic active/lexical duplicate convergence, refresh/rebuild projection parity, an atomic immutable-directory publication contract, and before/after elapsed/RSS/I/O measurements; [behavior, publication contract, verification, and benchmarks](docs/refresh.md).

- [x] **R4.2 — Live reading with bounded updates.** Once R4.1 and R1 paging exist, add opt-in updates that preserve reading position, filters, open blocks and page continuity. Select polling/long-polling or SSE based on measured load; evaluate C1 here. Show last successful import, source observation time and disconnected/stale states separately from lifecycle status. No live-process claim from file modification time alone. Test reconnects, replacements, concurrent readers, archived sessions and call/result pairs across updates. Document actual update latency and required collector or copy workflow. Delivered with a five-second authenticated revision probe, revision-triggered 50-event server-rendered replacement, per-tab opt-in, stable-anchor open/viewport restoration, filter/section continuity, recent/stale source observations, explicit browser connection states, atomic refresh visibility, hidden-session parity, automatic nullable schema migration, concurrent replacement/archive/tool-pairing regressions, and measured sub-1.2 ms p95 probe latency; [protocol, semantics, workflow, decisions, measurements, and verification](docs/live-reading.md).

- [x] **R4.3 — Source health and optional collection.** First expose sanitised discovery/parse failures, partial counts, ingest duration and per-source freshness in an authenticated health view and CLI diagnostic command. Later design opt-in collectors that export a versioned, minimal machine/session summary to an application-owned location; opening a page must not initiate SSH. Preserve source IDs, distinguish summary-only sessions from transcript-backed sessions, and label missing transcript drill-down. Require an explicit collection/redaction policy, transport authentication, replay/deduplication rules and retention limits. Test stale/offline machines and clock skew. Never collect authentication files or execute attach commands supplied by metadata. Delivered with a bounded authenticated view, sanitised CLI output, opaque stable file IDs, fixed failure codes, direct-home privacy, stale/unavailable/future-skew semantics, and a push-only collector contract covering versioning, explicit allowlist/redaction policy, authenticated transport, replay/deduplication, retention, summary-only enrichment, and forbidden authentication/attach data; optional collection remains disabled pending implementation of that gate; [semantics, command, and collector design](docs/source-health.md).

## R5 — Wider observability

- [x] **R5.1 — Validate a second agent adapter.** Gemini CLI was selected from its official open-source recording contract and implemented behind a dedicated adapter. Current JSONL and legacy JSON chats support upstream checkpoint/rewind behavior, tolerant malformed/unknown records, ordinary and adapter-specific transcript rendering, embedded tools, model evidence, best-effort workspace attribution, and non-additive per-turn usage without inventing lifecycle, aggregate-accounting, pressure, or turn-completion capabilities. Synthetic mixed-agent regressions cover shared host/project views, source-scoped identity collisions, initial/resumed presentation, direct-home refresh, and rebuild parity; see the [pinned raw-format contract and limitations](docs/gemini-adapter.md) and [adapter verification](docs/source-adapters.md).

- [x] **R5.2 — Optional operational metrics.** An authenticated Prometheus 0.0.4 endpoint now exposes fixed-cardinality gauges for indexed ingest/source health and supported session, token-availability, tool, and turn outcomes. Agent, status, freshness, outcome, reason, and model-family labels use fixed buckets; adversarial regressions exclude prompts, titles, session/source IDs, host/user identities, paths, raw model values, errors, and tool data. Values explicitly represent the disposable indexed snapshot/history rather than process-lifetime counters, with tested restart stability, full-rebuild reconstruction, response bounds, and aggregate-scan performance. The core UI has no monitoring dependency and no Grafana example is included without deployment demand; see the [metric, privacy, lifecycle, and load contract](docs/operational-metrics.md).

## M — Accounts and access

These four requirements were carried forward from TODO and now define the completed shared-deployment access gate. The framework decision preceded account work; authentication, source visibility, and independent persistent mappings are implemented before any durable per-user annotations or saved views.

- [x] **M1 — Choose the authentication approach before shared deployment.** Locally provisioned application identities now use salted Argon2id hashes and opaque server-side sessions in a separate persistent SQLite state file. Browser login rotates identifiers; explicit POST logout deletes the current session; inactivity and absolute lifetimes are enforced; reset, disablement, and generation-based administrator revocation invalidate every account session immediately. Owner-only password files and CLI create/reset/disable/enable/revoke operations define provisioning and recovery without public registration. Every data route remains protected, login/logout are CSRF-checked, return paths are same-origin, and Prometheus retains individual-account Basic authentication; see the [operational and security contract](docs/application-authentication.md).

- [x] **M2 — Define and enforce access permissions.** Administrators can see every source and use installation-wide health and metrics; viewers see only explicitly granted stable source IDs. Server-side scope now covers lists, search, filter values, aggregates, diagnostics, transcripts and every child/detail/export/live route, with hidden stable IDs returning `404`. Viewer health/metrics and unknown future routes fail closed with `403`; role and grant changes take effect on existing sessions. Local CLI create/set-role/grant/revoke/inspect operations and two-account synthetic regressions define the administrative boundary; see [application access permissions](docs/access-permissions.md).

- [x] **M3 — Persist accounts and permissions independently of the index.** Opaque application identities, password hashes, sessions, roles, and source grants live in the owner-only state database, distinct from indexed operating-system users. Grants use reproducible `src_…` identities rather than disposable row IDs; a full-rebuild regression preserves them and a changed logical source safely matches no stale grant. Schema v1 accounts migrate to administrators, schema v2 records roles/grants, and stopped-service backup/restore plus local role recovery are documented in [application authentication](docs/application-authentication.md) and [access permissions](docs/access-permissions.md).

- [x] **M4 — Review the framework choice before implementing account management.** Continue with Rust/Axum for M1-M3: established server-side session and Argon2id components can satisfy locally provisioned identities while preserving the tested importer, bounded query/UI layers, privacy controls, and single-service operations. Django offers a stronger built-in account/admin surface, but would still require custom source visibility, persistent/disposable database separation, and a wholesale regression-tested port. Reconsider only for a committed Django operating model, a substantially broader admin product, a blocked required identity integration, or measured deployment constraints; see the [framework, authentication, recovery, security, and reconsideration decision](docs/multi-user-framework-decision.md). This decision changes no runtime behavior.

M5 is post-gate account management, not a prerequisite for the current local-account deployment. Deliver it in the order below so later credentials and administrative surfaces reuse one policy and audit model. Items within a phase may be developed independently only when their stated prerequisites are already present.

| Phase | Roadmap items | Completion gate |
| --- | --- | --- |
| A — Self-service foundation | M5.1, then M5.2 | Typed per-account settings; app-owned session inventory and security-event ledger |
| B — Authorization and automation | M5.5a, M5.3, M5.5b | One server-side capability model scopes browser and token access before additional roles or teams ship |
| C — Administration | M5.6 | Every browser mutation is capability-checked, CSRF-protected, and audited; local CLI recovery remains available |
| D — Strong and federated identity | M5.4a, then independently gated M5.4b/M5.4c | Recovery, secret/key handling, reauthentication, and revocation are defined for each mechanism |
| E — Outbound notifications | M5.7 | An explicit delivery, credential, redaction, retry, and retention design is accepted before enabling egress |

- [x] **M5.1 — Typed user preferences and personalization.** Add an independently migrated per-account settings table in `agent-lens-state.sqlite`; do not store an unchecked JSON bag or write preferences into the disposable index. Start with an explicit timezone mode (`UTC`, browser-local, or validated IANA name), date/time format, `system`/light/dark/high-contrast appearance, font scale, bounded page size, live-reader interval/paused default, transcript detail/code-wrap defaults, and a validated default sessions view. Apply timezone semantics consistently to session, turn, usage, and diagnostic views while retaining raw UTC evidence. Ignore or default unknown values safely so rollback and forward-compatible upgrades do not prevent sign-in. Verify two-account isolation, invalid/stale settings, accessibility without client scripting, schema migration, and bounded query/render behavior. Delivered with state schema v3, a CSRF-protected account form, field-level forward-compatible fallback, DST-correct named/browser-local time handling, authenticated no-script styling, bounded 25/50/100-row views, persisted live/transcript/session defaults, and synthetic migration/isolation/render/query regressions; see [user preference semantics and operation](docs/user-preferences.md).

- [x] **M5.2 — Session inventory, self-service revocation, and security events.** Introduce app-owned session metadata linked to accounts, because the current generic session payload alone is not an adequate query or audit model. Show login time, last activity, current/expired state, and a bounded user-agent summary on `/account/sessions`; support revoking one session and “all other sessions” without terminating the confirmed current request. Collect/display network addresses only under an explicit trusted-proxy configuration, label the observed peer/proxy source, and define retention before storing them. Add an append-only, allowlisted security-event ledger for successful and failed sign-ins, password changes/resets, session revocations, account enable/disable operations, role/grant changes, and later MFA/token/admin events. Never record passwords, cookies, token values, transcript data, arbitrary headers, or unbounded errors. Display password age and an optional display name; defer notification email until M5.7 establishes its purpose and lifecycle. Verify identifier rotation, expiry, revocation races, pagination, retention, CSRF, account isolation, username-enumeration resistance, and sanitised rendered output. Delivered with state schema v4, lazily adopted legacy sessions, immediate server-side revocation, allowlisted client summaries and event types, 30-day session history and 180-day event retention, bounded per-account pages, optional escaped display names, password age, and no network-address collection pending an explicit trusted-proxy design; see [session inventory and security history](docs/session-security.md).

- [x] **M5.3 — Scoped personal access tokens and API authentication.** First inventory the API/CLI use cases and land the M5.5a capability vocabulary. Generate high-entropy `al_pat_...` bearer values, reveal each only once, and persist only a versioned one-way digest plus a short non-secret identifier—not the token or a password-style reusable secret. Require a description, least-privilege scopes, an expiry bounded by policy, last-used metadata, explicit revocation, and account disablement/role/grant enforcement on every request. Keep browser cookies and CSRF rules separate from bearer authentication; define accepted endpoints, response formats, rate limits, and log redaction rather than making every HTML route token-accessible. Verify scope denial, source isolation, expiry/revocation races, constant-time verification, audit events, bounded token listing, and absence of bearer material from logs and responses. Delivered with schema-v5 digest-only tokens, one-time reveal, one explicit read scope for metrics/redacted postmortems/live status, password confirmation and CSRF-protected management, 1–90-day expiry, current capability/source checks, atomic final authentication and revocation, creation/request limits, bounded listing/retention, audit migration, and synthetic security regressions; see [personal access token contract](docs/personal-access-tokens.md).

- [ ] **M5.4 — Strong and federated authentication as separately gated increments.** Do not bundle three credential systems into one release.
  - [x] **M5.4a — TOTP second factor.** Specify which roles/deployments require MFA, enrollment reauthentication, encrypted secret storage and key rotation, clock drift/replay handling, single-use recovery codes, reset/recovery through the local administrator boundary, and remembered-session policy. Add throttling and audit events without disclosing whether an account exists. Delivered as opt-in MFA for all roles with per-account administrator-required enrollment and reset/release controls, password-confirmed session-bound setup, encrypted secrets and durable versioned key rotation, one-use recovery digests, atomic time-step replay defense, limited enrollment sessions, persisted verification budgets, fresh factors for sensitive mutations, credential revocation, no remembered-device bypass, schema-v8 migration, and local missing-key recovery; see [TOTP MFA policy and operation](docs/totp-mfa.md).
  - [x] **M5.4b — WebAuthn/passkeys.** Proceed only after deciding second-factor versus passwordless use, relying-party ID/origin behavior behind HTTPS proxies, discoverable-credential policy, sign-counter limitations, device naming, multiple credentials, and recovery. Prefer a maintained WebAuthn implementation and verify challenge expiry, origin/RP validation, replay resistance, deletion, and account disablement. Delivered as opt-in password-first second factors, gated by an explicit HTTPS origin/Secure cookies, with exact-host RP binding, required device verification, ten named credentials, shared MFA enforcement/recovery/reset, bounded server-only one-use challenges and action proofs, committed counter/revocation checks, schema-v9 migration, and signed software-authenticator/browser regressions; see [passkey policy and deployment](docs/passkey-second-factors.md).

Require discovery with issuer pinning, Authorization Code Flow with PKCE plus state/nonce checks, stable issuer+subject identity mapping, explicit local-role/team claim mapping, account-linking rules, local session lifetime, RP-initiated logout, provider-triggered revocation expectations, and CLI break-glass recovery. Do not accept email alone as a stable identity.
    - [x] Offline configuration preflight with mandatory provider/client/public URL and explicit administrator-provisioned issuer+subject links, locally managed permissions, logout, and break-glass policies. See [configuration preflight](docs/oidc.md); this does not enable sign-in.
    - [x] Explicit discovery preflight (`oidc-check --discover`): exact issuer pinning, code/S256/client-authentication/logout capability validation, bounded verified HTTPS without redirects, and synthetic-TLS transport regressions. Offline configuration validation remains the default; this does not enable sign-in.

  - [x] **M5.5a — Capability matrix.** Replace route-name role checks with typed server-side capabilities covering content read, aggregate/redacted reports, source refresh, annotations when implemented, account administration, audit read, and token management. Map existing `admin` and `viewer` behavior without widening access, fail closed for new routes, apply scope before counts/pagination, and use the same evaluator for sessions and PATs. Add route/query/export regressions for every capability. Delivered with a shared typed role policy, method-aware route classification, capability-based source predicates and operational handlers, tested credential-ceiling intersections for M5.3, disabled reserved capabilities, all-role fail-closed route regressions, and existing scoped query/export coverage; see [capability matrix and deployment](docs/capabilities.md). PAT authentication remains M5.3.
  - [x] **M5.5b — Teams and intermediate roles.** Add teams with stable IDs and many-to-many membership/source grants, deterministic union semantics, and explainable effective access.
